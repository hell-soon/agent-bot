# agent-bot

Свой ИИ-бот для GitHub: Claude Code и/или Codex работает **в фоне, от имени отдельного бота** (`имя[bot]`) в ваших репозиториях и приносит **pull request'ы** — сливаете вы. Управление — из терминала (`bot …`) или из панели в браузере (`bot ui`).

- задача из issue → ветка → код → проверки → PR;
- очереди и цепочки задач, правки PR по комментариям ревью;
- обсуждение фичи вопросами с вариантами ответа → спецификация → issue;
- живая лента: что бот читает, правит, запускает; план и изменённые файлы;
- лимиты подписки, токены, цена; при обрыве или лимите — «Продолжить» с того же места;
- память по каждому репозиторию: бот дописывает, что узнал, и в следующий раз тратит меньше;
- поиск и команды как в Spotlight (⌘K).

Работает на macOS (на Linux — с мелкими правками: уведомления, `caffeinate`).

## Как это устроено

```
 вы ── bot ui (127.0.0.1:4545) / bot … в терминале
          │
          ▼
     agent.sh ── Claude Code или Codex (в фоне, свои правила и запреты)
          │        │
          │        └─ рабочая копия репозитория: work/<owner>__<repo>
          ▼
     GitHub App «имя[bot]» ── токен на 1 час на каждый git push / gh
```

Бот — это **GitHub App**, а не второй аккаунт: его нельзя «ограничить» как новый аккаунт, права — только на выбранные репозитории, в истории видно, что работал бот.

## Установка

### 1. GitHub App

1. GitHub → **Settings → Developer settings → GitHub Apps → New GitHub App**.
2. Имя — как будет называться бот (`имя[bot]`). Homepage URL — любой, например ссылка на этот репозиторий.
3. **Webhook → Active** — снять галочку.
4. **Repository permissions**: Contents, Pull requests, Issues — **Read and write** (Metadata — Read-only само).
5. **Where can this GitHub App be installed?** — Only on this account → **Create GitHub App**.
6. На странице приложения: запишите **App ID**, внизу — **Generate a private key** (скачается `.pem`).
7. Слева **Install App** → Install → **Only select repositories** → выберите репозитории для бота.

### 2. Сам бот

```bash
git clone https://github.com/hell-soon/agent-bot.git ~/agent-bot
cd ~/agent-bot && ./setup.sh
```

`setup.sh` проверит зависимости (`git gh jq node openssl curl`, Node 20+, и хотя бы один ИИ — `claude` или `codex`), соберёт панель, спросит App ID и путь к `.pem`, сам узнает имя бота и доступные репозитории, создаст `bot.env` и команду `bot` в `~/.local/bin`. Повторный запуск безопасен.

### 3. Вход в ИИ

Нужен хотя бы один — какой есть, тот и работает; установлены оба — переключаются в панели.

- **Claude**: `claude` → войти. Для работы без присмотра лучше `claude setup-token` и вставить токен в `bot ui` → Настройки.
- **Codex**: `brew install codex && codex login`.

### 4. Запуск

```bash
bot ui      # панель в браузере
bot help    # команды терминала
```

## Команды

```
bot ui                  панель в браузере (bot ui stop — выключить)
bot                     обычная сессия от имени бота
bot 5                   сделать issue #5
bot q 5 6 7             очередь: каждое — свой PR от main, без вопросов
bot chain 5 6 7         цепочка: каждое следующее поверх предыдущего
bot q ready             все открытые issue с меткой ready-for-agent
bot pr 7 ["текст"]      поправить PR #7 (по ревью или как сказано)
bot idea "текст"        обсудить фичу (вопросы → спецификация → issue)
bot bug "текст"         разобрать баг
bot -r owner/repo …     в другом репозитории (или запуск из папки репозитория)
bot --ref owner/x …     подсмотреть в другом репозитории (только чтение)
BOT_AI=codex bot 5      разово другим ИИ;  BOT_MODEL=opus BOT_EFFORT=high …
```

Метки размера issue `size:s` / `size:m` / `size:l` выбирают модель: Haiku / Sonnet / Opus (у Codex — усилия).

Скиллы [mattpocock/skills](https://github.com/mattpocock/skills) (`/implement`, `/triage`, `/to-tickets` …) подхватываются, если плагин установлен в Claude Code. Для нового репозитория: `bot -r owner/repo "/setup-matt-pocock-skills"`.

## Обновление панели

Откройте **Настройки → Обновление панели**, чтобы проверить версию из `main` репозитория `hell-soon/agent-bot`. Кнопка **Обновить** собирает её в отдельной папке с помощью Bun, ждёт завершения текущей работы и переключает сервер и интерфейс вместе. Если новая версия не запускается, панель возвращается к предыдущей. Для переключения на новый интерфейс обновите страницу браузера.

Переключатель **Обновлять панель автоматически** выключен по умолчанию. Если его включить, панель проверяет обновления при запуске и каждые 15 минут. Выключение останавливает следующие проверки. Уже начатая установка может завершиться.

Для первого перехода на эту схему обновите папку установки и перезапустите панель командами `bot ui stop` и `bot ui`. Панель запоминает выбранную версию, а настройки, задачи и журналы остаются в папке установки.

## Настройки и скиллы

В панели: **Настройки** (⌘,) → разделы:

- **Репозиторий** — ИИ и модель для этого репозитория, базовая ветка, команды проверки, PR черновиком / ревьюеры / метки и **авторабота**: бот сам берёт issue с `ready-for-agent`, чинит упавший CI и конфликты в своих PR, отвечает на новые ревью (не больше N задач в день, CI — не больше 3 попыток подряд; работает, пока запущен `bot ui`).
- **Скиллы** — все скиллы бота с описанием, вкл/выкл (меньше включено — меньше стартовый контекст), установка наборов из GitHub (`owner/repo`). В строке ввода `/` подсказывает скиллы, в поиске ⌘K — тоже.
- **Правила** — ваши инструкции боту: общие (`rules/_global.md`) и для репозитория. Обязательные правила (не пушить в базу, не сливать PR, не трогать секреты) действуют всегда.
- **Разрешения** — какие команды можно в фоне сверх базовых (`bun`, `pnpm`, `make`…) и что запретить.
- **Уведомления и сторож** — сообщать, когда PR готов, бот ждёт ответа или задача не получилась: в macOS, во вкладке браузера и в Telegram (свой бот от @BotFather — токен в `keys/telegram-token`). Сторож останавливает задачу, которая молчит дольше N минут, идёт дольше N минут или повторяет одно и то же без правок; правки сохраняются, «Продолжить» — с того же места.

**Архитектура** (в боковой панели или ⌘K) — схема проекта колонками «Клиенты → Вход → Сервисы → Платформа → Внешние системы», связи по типам (HTTP, данные, события, метрики), виды-вкладки, поиск, схема/список, масштаб. Хранится в самом проекте — `docs/architecture.json` (формат — в `ui/arch-scan.mjs`). Пока файла нет, показывается черновик сканера без ИИ (docker-compose, зависимости, `.env.example`, адреса API в коде); «Создать/Обновить с ИИ» — бот (Claude или Codex) проверяет его по коду, дописывает связи и приносит PR.

**Знание проекта** (Настройки → Репозиторий): перед задачей бот получает **карту проекта** — слои и слайсы, общие модули и что похоже на задачу (из графа импортов, без ИИ; меньше поиска — меньше токенов). Когда бот открыл или обновил PR, в нём появляется комментарий **«Что может задеть»** — кто использует изменённые слайсы.

**Проверки PR бота** (Настройки → Репозиторий): в комментарии «Что может задеть» — ещё **новые нарушения FSD** (граф ветки PR против базовой; в панели — кнопка «Починить»). Для правок интерфейса — **скриншоты до/после**: страницы, которые используют изменённое, на телефоне и десктопе; «до» — сайт, «после» — превью PR (деплои GitHub или шаблон адреса). Картинки — в ветке `agent-bot-screens`. Закрытые превью: секрет обхода защиты Vercel и cookie входа хранятся в `keys/screens/`; «Пробный снимок» показывает, что видит браузер. Нужны браузеры Playwright (`npx playwright install chromium`).

**Проверка документации после слияния** включается в Настройки → Репозиторий → Знание проекта. Панель проверяет PR, слитые в базовую ветку с момента включения, и при запуске разбирает пропущенные слияния. В корневом `README.md` и Markdown-файлах в `docs/` она ищет точные совпадения с изменёнными командами, примерами и переименованными путями. На главной видны PR, устаревшая строка и предлагаемая замена. Кнопка «Создать issue» публикует выбранную находку в GitHub.

**Обновление зависимостей** настраивается в разделе «Репозиторий». Укажите npm-пакеты, день и время по часовому поясу панели. Пустой список выключает расписание. Поддерживаются прямые зависимости с точной версией или префиксом `^`/`~` в `package.json` рядом с закоммиченным `package-lock.json`, `pnpm-lock.yaml` или `bun.lock`. По умолчанию бот выбирает стабильные patch-версии, а по настройке включает minor. После простоя панель проверяет последнее пропущенное срабатывание и собирает подходящие версии в один черновик PR.

Для обновлений панель запускает «Команды проверки» из корня репозитория. Указывайте каждую команду с новой строки. Команды из `AGENTS.md` или `CLAUDE.md` нужно перенести в это поле. Если в проекте нет таких файлов и поле пустое, запускаются доступные скрипты `typecheck`, `lint`, `test` и `build` из изменённых `package.json`. Результат, пропущенные пакеты, причина сбоя и ссылка на черновик доступны рядом с расписанием.

**Граф проекта** — как в Obsidian, из кода без ИИ: файлы и импорты базовой ветки (JS/TS/Vue, Python, Go; алиасы tsconfig, Nuxt, Vite), уровни «слайсы/папки» и «файлы». FSD узнаётся сам (и с номерами слоёв: `00.shared … 06.app`): слои — полосами сверху вниз, нарушения (импорт верхнего слоя, соседнего слайса, мимо `index`) — красным. Слой «Работа бота» подсвечивает файлы, которые бот правил. **Схема задачи** (вкладка в задаче) — этапы работы на оси со временем.

В задаче с PR — итог: состояние, проверки (упали — «Починить CI»), конфликты («Разрешить»), ревью и изменённые файлы с diff.

## Правила проекта

Бот читает `AGENTS.md` / `CLAUDE.md` репозитория: там должны быть команды проверки (typecheck, тесты, сборка). Нет файла — бот возьмёт скрипты из `package.json`. Сделать его: `bot -r owner/repo "/init"`.

## Безопасность

- В фоне бот может только править файлы в своей копии, `git`, `gh`, `npm`/`npx`/`node` и чтение. Запрещены `gh pr merge`, force push, push в `main`.
- У **Codex** таких запретов по командам нет — только песочница и правила. Поэтому **защитите `main`**: репозиторий → Settings → Rules → Rulesets → New branch ruleset → Target: default branch → **Restrict updates**, **Block force pushes**; в Bypass list — себя (Repository admin, Always allow). Тогда в `main` попадает только то, что сливаете вы.
- Пуш в базовую ветку бот не сделает и без Rulesets: в его копии репозитория стоит git-хук `pre-push`, который это отклоняет (и для Claude, и для Codex). Это защита от ошибки, а не от умысла — Rulesets всё равно лучше.
- **Репозиторий в чужом аккаунте или организации**: приложение → Advanced → **Make public**, затем Install App → нужный аккаунт → Only select repositories. Публичное приложение может поставить себе кто угодно, но без вашего ключа бот там ничего не делает, а панель и бот работают только с установками из `BOT_OWNERS` в `bot.env` (Настройки → «Доступ на GitHub»; чужие установки там же можно удалить).
- Секреты — только у вас: `keys/` (ключ приложения, токен Claude) и `bot.env` в git не попадают.

## Панель

Vue 3 + Vite + TypeScript: исходники — `ui/src`, сборка — `ui/dist` (её раздаёт `ui/server.mjs`; `setup.sh` и `bot ui` собирают сами).

```bash
cd ui
npm run dev        # горячая перезагрузка на :5173, запросы /api идут в запущенный bot ui
npm run build      # собрать
npm run typecheck  # проверить типы
```

## Где что лежит

| Путь | Что |
|---|---|
| `bot.env` | App ID, имя бота, репозиторий по умолчанию (создаёт `setup.sh`) |
| `keys/` | ключ GitHub App, токен Claude, токен Telegram-бота |
| `config.json` | настройки из панели |
| `memory/` | память бота по репозиториям |
| `rules/` | ваши правила боту |
| `skills/`, `.skills/` | установленные наборы скиллов и собранный плагин скиллов |
| `work/`, `refs/` | рабочие и справочные копии репозиториев |
| `logs/` | журналы запусков |
| `ui/` | панель: `src/` (Vue), `server.mjs` — сервер и очередь задач, `codex-adapter.mjs` |

Удалить: `rm ~/.local/bin/bot && rm -rf ~/agent-bot`, затем удалить приложение на GitHub.
